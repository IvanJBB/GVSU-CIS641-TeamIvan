# Software Requirements Specification (SRS) 

# Overview 

This Software Requirements Specification (SRS) defines the functional and non-functional requirements for my project, Platformer Hopper. Platformer Hopper, a 2D platforming game, was developed in Unity for Grand Valley State University's CIS 641 Systems Analysis and Design. This page will be updated over time, with its purpose being to establish expected functionality and requirements and provide a reference for this project's development. 


# Functional Requirements 

## Main Menu 

\- FR1: The game shall display a main menu immediately upon launch.
\- FR2: The main menu shall provide options to start the game or exit the application.

## Player Movements

\- FR3:The player character shall move left and right in response to directional inputs.
\- FR4: The player character shall jump when the designated jump key is pressed. 

## Pause Menu 

\- FR5: The game will show a pause menu when a designated pause key is pressed during active gameplay. 
\- FR6: The game shall suspend gameplay while the pause menu is active. 

## Goal Completion 
\- FR7: The game shall have a form of sensor/block to know when the player reaches the level goal.
\- FR8: The game shall display a victory screen when a level is completed. 


# Non-Functional Requirements 

## Performance 

\- NFR1: The game shall maintain smooth gameplay without noticeable performance degradation during normal operation.

## Responsiveness 

\- NFR2: Player movement controls will respond to user input without any substantial delay. 

## Compatability 
\- NFR3: The game will run successfully on a Windows system without requiring anything additional. 

## Usability 
\- NFR4: The user interface (UI) will be readable and scaled correctly for both menu navigations.
